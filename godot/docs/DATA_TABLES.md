# Excel 資料編輯流程

最新為 18 表，劇情區段、事件、台詞與關卡流程的欄位關係及範例見 [CHAPTER_FLOW.md](CHAPTER_FLOW.md)。區段命名獨立管理，通用失敗區段可跨關卡重用。

1. 關閉遊戲，以 Excel 編輯 `data/tables/GameData.xlsx`，先備份工作簿。
2. 保留第 1 列欄位名稱，從第 2 列編輯資料。ID 是關聯鍵，既有角色與職業 ID 不可任意改名。
3. 保存並執行專案根目錄 `Export_Data.cmd`（Python 3）。也可執行 `python tools/export_tables.py --check` 只驗證。
4. 匯出成功才會更新 `data/catalog.json`，舊版保留 `.bak`；重新啟動 Godot 遊戲載入。失敗會指出工作表／列號，不覆蓋現有 JSON。

工作表包括使用說明、職業、技能、角色、敵人、裝備、道具、掉落、寶箱、初始背包、初始裝備。職業與技能透過技能 ID 關聯；敵人與寶箱引用掉落表。多職業限制以 `|` 分隔，沿用範例格式。數量、HP、MP、射程必須為整數；機率 0–1，每列獨立判定，可同時掉多項。裝備數量包含已穿戴份數，不可超量分配。

2026-11-26 新增成長、等級、經驗獎勵三表，共 14 張工作表。成長百分點 100＝每級 +1，依等級累積後取整；等級表是累積經驗門檻；participation 與 kill 是參戰與擊殺獎勵。詳細數值及相容規則見 [LEVEL_SYSTEM.md](LEVEL_SYSTEM.md)。

只接受數值與文字，不接受公式；需要試算時請另開工作表／工作簿，將最終結果貼上為值。匯出器檢查重複 ID、缺欄、範圍、參照、裝備職業與初始分配。請勿直接修改產生的 JSON 作為長期資料來源，下一次匯出會覆蓋它。

初始背包與初始裝備只用於新隊伍。既有 `user_data/party.json` 不會隨表格重設；改平衡值後會在下次建立戰鬥單位時套用。改動數值可能使舊戰鬥快照不相容，請先完成現有戰鬥並保留資料備份。不要刪除仍被存檔使用的道具或裝備 ID。

目前為首版數值，尚未完成長期平衡調整。新增職業 ID 不會自動產生專屬圖示、剪影或技能邏輯；本版的特殊效果限定傷害與盾牆。

2026-11-26 新增「劇情事件」「劇情台詞」，共 16 張工作表。既有 13 張資料表內容保持不變。劇本 ID 關聯事件與台詞，事件關卡 ID 對應 levelId，台詞順序決定播放次序。欄位、觸發時機及上限見 [DIALOGUE_SYSTEM.md](DIALOGUE_SYSTEM.md)。
